# ADR-0002 · 1초봉을 모아 30초봉 생성

- 상태: 채택
- 날짜: 2026-10-27
- 저장소: [prismview-collector](https://github.com/PrismView/prismview-collector)

## 배경

초기 기획서는 커스텀 봉(30초, 13분 등)을 보류하고 OKX 표준 시간봉만 쓰기로 했다. 전략이 실제로 보는 봉은 30초봉이다. OKX `bar`에는 1s, 1m는 있어도 30s는 없다. 거래소가 주지 않는 봉을 쓰려면 더 짧은 봉을 직접 집계해야 한다.

## 결정

OKX `history-candles`로 **1초봉**을 받고, 수집기가 30개를 묶어 **30초봉**을 만든다.

- 버킷 시작: `ts / 30_000 * 30_000` (UTC epoch ms)
- open = 버킷 안 첫 1초봉의 open
- close = 마지막 1초봉의 close
- high = MAX(high), low = MIN(low)
- vol / volCcy / volQuote = SUM
- 1초봉 30개가 모두 있을 때만 "완전" 30초봉으로 표시한다

1차 백필 범위는 **3개월**, 종목은 BTC-USDT-SWAP · ETH-USDT-SWAP이다.

## 검토한 대안

| 대안 | 쓰지 않은 이유 |
| --- | --- |
| OKX 1분봉만 저장 | 전략 봉과 해상도가 다르다. 30초 안의 고가·저가를 1분봉으로는 복원할 수 없다. |
| OKX 체결(trade)로 30초봉 생성 | 정확도는 더 높을 수 있으나 데이터 양·호출 제한·구현 비용이 1차 범위에 비해 크다. |
| 30초봉만 받고 1초봉은 버린다 | OKX가 30초봉을 주지 않는다. 집계 규칙을 바꿔 다시 만들 원본도 사라진다. |

## 이유

1. **전략과 데이터가 같은 시간축이어야 한다.** 백테스트 체결 판정은 30초봉의 고가·저가에 의존한다.
2. **1초봉이 있으면 30초봉을 다시 만들 수 있다.** 집계 버그를 고쳐도 원본에서 재적재하면 된다.
3. **리페인팅을 막는다.** `confirm = 1`인 1초봉만 저장·집계한다. 진행 중 봉의 고가·저가를 쓰면 과거 결과가 실제보다 좋아 보인다.

## 결과 · 대가

- 3개월 × 2종목 1초봉 ≈ 1,560만 행. 1분봉만 둘 때보다 저장량이 커진다. 그래서 [PostgreSQL](0001-postgresql.md)과 [누적 저장](0003-cumulative-storage.md)을 같이 정했다.
- OKX가 1초봉을 몇 개월까지 주는지는 구현 직전 공식 문서로 확인한다. 부족하면 받은 구간만 적재하고 `known_gaps`에 남긴다.
- 호출 횟수가 늘어나므로 레이트 리밋(history-candles는 요청당 최대 100개)을 지킨다.

## 다시 검토할 조건

전략 시간봉이 바뀌거나, OKX가 30초봉을 공식 제공하거나, 1초 히스토리 깊이가 3개월에 못 미치면 원본 단위를 다시 정한다.
