# ADR-0003 · 원본·집계 봉을 DB에 누적 저장

- 상태: 채택
- 날짜: 2026-10-27
- 저장소: [prismview-collector](https://github.com/PrismView/prismview-collector)

## 배경

정리노트의 기본안은 "1분봉만 저장하고, 상위 시간봉은 조회 시 SQL로 즉석 집계"였다. 이번 수집기는 원본이 1초봉이고 전략 봉이 30초봉이다. 백테스트와 차트가 같은 30초봉을 반복해서 읽는다. 매번 1초봉 30개를 묶어 주면 조회마다 집계 비용이 나고, 집계 규칙이 코드와 쿼리에 흩어진다.

## 결정

**누적 저장**한다.

1. 1초봉을 `candles` 테이블에 계속 붙인다. 오래된 행을 지우거나 롤링 윈도로 자르지 않는다.
2. 30초봉도 같은 테이블에 `timeframe = '30s'`로 저장한다. 조회 시점에 즉석 집계하지 않는다.
3. 기본키 `(inst_id, timeframe, ts)`로 중복을 막고, 같은 봉을 다시 받으면 upsert한다.
4. 30초봉은 1초봉에서 다시 만들 수 있으므로, 집계 로직이 바뀌면 해당 구간만 재집계한다.

## 검토한 대안

| 대안 | 쓰지 않은 이유 |
| --- | --- |
| 1초봉만 저장, 30초봉은 조회 시 집계 | 3개월 스캔을 백테스트마다 반복한다. 구성 봉 개수 검사도 조회 경로에 묶인다. |
| 30초봉만 저장 | 집계 버그를 고치면 원본이 없어 복구가 안 된다. [ADR-0002](0002-30s-candle.md)와 충돌한다. |
| 최근 N일만 남기고 삭제 | 백테스트 기간이 줄어든다. 이 프로젝트의 목적은 과거 검증이다. |

## 이유

1. **읽는 경로가 단순해진다.** 차트와 백테스터는 `timeframe = '30s'`만 조회하면 된다.
2. **완전성을 저장 시점에 확정한다.** 1초봉 30개가 있는 버킷만 30초봉으로 넣고, 모자라면 만들지 않거나 `known_gaps`와 함께 표시한다.
3. **멱등이다.** 노트북을 며칠 꺼 두었다가 켜도 "마지막 저장 ts 이후"만 이어 받으면 된다. 히스토리를 지우지 않으므로 빈 구간이 영영 사라지지 않는다.

## 결과 · 대가

- 디스크를 1초봉 + 30초봉만큼 쓴다. 30초봉은 1초봉의 약 1/30이라 용량의 대부분은 1초봉이다.
- 원본과 집계가 어긋날 수 있으므로, 재집계 명령과 누락 검사를 수집기에 둔다.
- 파티셔닝은 지금 규모에선 하지 않는다. 수억 행이 되거나 오래된 데이터를 통째로 버릴 일이 생기면 그때 본다.

## 다시 검토할 조건

조회가 느려지거나, 1초봉 보관 비용이 부담이 되면 1초봉은 최근 구간만 두고 30초봉+Parquet를 장기 보관하는 계층을 검토한다.
